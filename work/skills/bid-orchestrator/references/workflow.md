# 流程细则

## 阶段一：ANALYZE

1. 确认项目目录 `projects/<项目编号>/` 已创建
2. 投标助理读取招标正文、采购需求、附件格式
3. 产出 `00_项目概览.yaml`、`01_要求矩阵.md`、`02_废标项清单.md`、`03_评分点清单.md`、`04_任务清单.md`
4. 校验符号计数与评分细则是否一致

输出确认：

- 每条要求有原文引用、章节、页码、符号、风险等级
- 废标项与评分项分表
- 符号计数核对结论已写入

## 阶段二：GATHER

1. 文档秘书登记企业资料
2. 每份资料分配证据编号 `EV-nnn`，对照要求矩阵标注适用条款
3. 缺失项写入 `11_资料缺口清单.md`，注明影响条款
4. 产出 `10_证据索引.md`、`11_资料缺口清单.md`、`12_版本记录.md`

输出确认：

- 每份资料有来源、日期、有效期、适用条款、盖章状态
- 每个高风险佐证要求（截图、证书、备案、案例）都有状态

## 阶段三：DRAFT

1. 售前助手读取要求矩阵、评分点、证据索引、缺口清单
2. 搭建提纲，每个评分点标注归属章节
3. 撰写实施方案、售后方案、技术方案、服务应答表初稿
4. 产出 `30_`、`31_/`、`32_` 文件

输出确认：

- 每段有标记
- 无既成事实表述出现在 `[合理拟定]` 内容中
- 文末有缺口汇总

## 阶段四：REVIEW

1. 文档审查员按五个维度检查
2. 输出三级问题清单，每条问题带六个要素与回流目标
3. 产出 `40_问题清单.md`、`41_附件与签章检查表.md`、`42_最终提交检查表.md`

## 阶段五：REMEDIATE

按问题分类回流：

```
Q-xxx 要求理解 → ANALYZE → 重新抽取 → 更新 01-04
Q-xxx 资料缺失 → GATHER → 登记证据 → 更新 10-12
Q-xxx 内容缺陷 → DRAFT → 修改方案 → 更新 30-32
```

回流后重新运行 REVIEW，直到阻断与重大问题全部关闭。

## 阶段六：FINALIZE

文档秘书：

1. 生成最终目录
2. 统一版式
3. 核对附件顺序符合第六章列举顺序
4. 完成 `42_最终提交检查表.md`

## 阶段七：HANDOFF

总控输出人工任务清单：

```markdown
## 待补充资料
| 项 | 需要什么 | 影响条款 | 找谁 |

## 待确认决策
| 项 | 需要决定什么 | 确认人 | 截止 |

## 禁止直接使用内容
| 位置 | 内容 | 需要什么证据 |

## 盖章与签署位置
| 文件 | 位置 |

## 平台提交注意
- 加密、解密时限
- 电子印章与数字证书
```
